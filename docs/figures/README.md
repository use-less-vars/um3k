# Figures for the report

This directory is the include root the report actually reads. `docs/report/main.tex` is built from inside
`docs/report/`, and every graphic in the chapters is pulled in as
`\includegraphics[width=0.XX\textwidth]{../figures/NAME.png}`, i.e. from **`docs/figures/`**, not from
`docs/report/figures/`. Most chapters name the `.png`; the mode-shape pair is the exception and names the `.pdf`
(`fig_ez_before_after.pdf`, `fig_ey_before_after.pdf`), which is the vector original. **`sec_modes.tex` never
includes a `.png`**: the `.png` beside each `.pdf` is a raster preview only (400 dpi), for reading on screen or
zooming into a single panel. The two files of a pair are written from the same matplotlib figure.

The `cavity_*`, `energy_drift`, `abc_duct`, `scatter-*`, `rcs-*` and `ms-*` files are study outputs, described in
`docs/OUTLINE.md` and regenerated by their studies; they are not documented again here.

## The current pair: `fig_ez_before_after` / `fig_ey_before_after`

This is what `docs/report/sec_modes.tex` includes now, under the labels `fig:mode-ez-pairing` and
`fig:mode-ey-pairing`. Two figures, three rows by two columns, from the two banked eigensolves of the same
microstrip cross-section: PMC / open top (`c1_spectrum.npz`, QZ column 738) and PEC / closed box
(`pecbox_spectrum.npz`, QZ column 699). Rows: analytic / superseded, extracted / corrected, difference. Column
headers `PMC / open top` and `PEC / closed box` sit once, above the top row of each column, in bold.

`fig_ez_before_after` is the `e_z` story: row 1 the superseded mis-pairing (analytic *vertical* reference
against the extracted *longitudinal* field, `corr` `+0.1192` / `+0.1473`), row 2 the repaired pairing (vertical
against vertical, `+0.9353` / `+0.9369`), row 3 the difference (`max abs Delta` `5.87` / `5.86`, `rms/rms`
`1.24` / `1.23`). `fig_ey_before_after` is the `e_y` control: the same reference, metric and plotting path on
the component the mis-pairing never touched (`+0.9208` / `+0.9123`, difference `max abs Delta` `16.16` / `16.04`,
`rms/rms` `0.40` / `0.42`).

Sizing, measured from the committed PDFs rather than asserted: each figure is `430.866 x 547.2` pt MediaBox, set
to `width=0.95\textwidth` = `432.48` pt, so the LaTeX scale is `1.003746` and each figure prints
`432.480 x 549.250` pt. The `\textheight` is `700.2` pt, so a figure and its caption take 78 per cent of the
text block and still fit one page. Panels print at about `86` pt square. Type sizes in the content stream,
printed: `11.04` pt for tick labels, panel titles and the note; `11.54` pt for the axis labels; `16.06` pt for
the figure head, whose one mathtext subscript prints at `11.24` pt. **The minimum over all text runs is `11.04`
pt.**

Three defects were found in the previous generation of these two files and fixed with it; all three were silent
because `savefig(bbox=None)` clips to the canvas without warning. The column headers were annotated at an axes
fraction that put them above the top of the canvas, so `PMC / open top` and `PEC / closed box` were drawn
entirely off the page (now placed in points above the axes top). The right margin left `6.5` pt for colourbar
tick labels that need about `30` pt, so **the PEC colourbars printed with no numbers at all** (the right margin
now reserves `34` pt). And the note line was `478` pt wide on a `431` pt canvas, so it was clipped by `24` pt on
both sides (now three short lines).

## The mode-shape pair (C2b), superseded single-page form

The two sections below describe the earlier single-page pair `mode_shape_mispaired_before.*` /
`mode_shape_corrected.*`, which `sec_modes.tex` no longer includes. Those files are retained: nothing is
deleted.

One figure, drawn twice, from two banked eigensolves of the same microstrip cross-section: PMC / open top
(`c1_spectrum.npz`, QZ column 738) and PEC / closed box (`pecbox_spectrum.npz`, QZ column 699). Each figure is a
single page laid out as columns PMC | PEC | text and rows analytic `e_z`, extracted `e_z`, difference, then the
same three for `e_y`. Panels, axes and colour limits are identical between the two figures — the limits are the
per-panel maximum over *both* metrics — so the before and after pictures can be flipped between without any panel
moving or rescaling.

The pair is a correction, and the correction is in one row only. **Before**: the `e_z` row correlated the analytic
*vertical* reference with an extracted *longitudinal* field (`e_z_superseded = -interp(beta*z_free)`), two different
physical components. The arithmetic is right and the comparison is wrong, which is why that row reads as a
catastrophic disagreement (correlation `0.1192` / `0.1473`, difference rows full-scale) when the mode is in fact
fine. **After**: the same row correlates vertical against vertical (`e_z_vv`, component 1 of `e_t` sampled on the
`A_ez` lattice), and it reads `0.9353` / `0.9369` with the difference rows down to `max|Δ|` `6.74` / `6.72`. The
`e_y` rows (width against width) were never affected and are identical in the two figures, `0.9208` / `0.9123`;
that row is the built-in control which shows the panels did not change between the two runs.

Nothing is solved to draw these. The scripts read the banked spectra and the banked eigenvectors and refuse to
draw unless all three banked correlations reproduce to `1e-6`.

## Provenance

* Generator of the current pair: `tools/host/mode_plot/make_before_after_figs.py`
  (`python3 tools/host/mode_plot/make_before_after_figs.py`, about `8` s, no arguments). It sets
  `FIG_W = 0.95 * \textwidth` so the inclusion scale is `1.0`, imports `mode_plot.reconstruct_run` for the fields,
  and prints the reproduced correlations as a self-check before it writes anything. Constants, if you re-tune it:
  `FIG_W = 5.984254` in, `FIG_H = 7.60` in, `font.size 11.0`, `axes.labelsize 11.5`, `axes.titlesize 11.0`,
  `figure.titlesize 16.0`; the GridSpec is `left 0.085`, `right 0.916` (that margin is the colourbar label room),
  `top 0.815`, `bottom 0.150`, `hspace 0.62`. Raising the type further needs a taller figure, not a wider
  inclusion: the panels are square over a `12.1 x 12.1` mm extent, so at `431` pt of width they are height-bound
  and roughly `120` pt of horizontal slack is intrinsic.
* Generator of the superseded single-page pair: `tools/host/mode_plot/mode_plot.py` (driver
  `tools/host/mode_plot/run.sh`, log `tools/host/mode_plot/out/run.log`). It reconstructs `e_y` and `e_z_vv` from the banked `e_t` eigenvector with
  `emfit`'s `Mode2D.e_at` on the two plane lattices, and rebuilds the longitudinal `e_z` through the audit's own LU
  route — no new solve.
* Banked inputs: `tools/host/c1-audit/out/c1_spectrum.npz` (PMC) and `tools/host/c1-audit/out/pecbox_spectrum.npz`
  (PEC), produced by `c1_audit.py` / `pecbox_variant.py`.
* Numbers quoted above match the printed panel text on the figures (`corr_ez_vv` `+0.935287` / `+0.936930`,
  `corr_ez_superseded` `+0.119160` / `+0.147291`, `corr_ey` `+0.920771` / `+0.912343`, `eps_eff` `3.629512` /
  `3.606095`).

## Two caveats a reader of the report will hit

Both caveats below are about the **superseded single-page pair**, `mode_shape_mispaired_before.*` and
`mode_shape_corrected.*`. They do not describe `fig_ez_before_after.*` / `fig_ey_before_after.*`, which are the
files the chapter includes.

1. **The in-figure text of the superseded pair is stale about its own filenames.** The text column prints the paths the script was
   hard-wired to at the time (`docs/report/figures/c2b_mode_shape_corrected.pdf` and
   `docs/design/mispaired_metric_before.pdf`). The files here are byte-identical copies of those, under the names
   the chapter uses; nothing inside the panels has been redrawn. Changing the printed path means editing
   `mode_plot.py` and re-running it.
2. **The `3.5` pt figure belongs to the superseded pages, not to the included ones.** Each *superseded* figure
   is one page of `921.3 × 793.8` pt (`12.80 × 11.02` in, landscape), panels rasterised at `200` dpi, in-figure
   text drawn at roughly `7` pt. Fitted to `\textwidth` (~`6.5` in) that text printed at about `3.5` pt
   (`7 × 0.4694 = 3.29` pt, once the `921.3` pt page is scaled to `432.48` pt), legible only by zooming into the
   PDF. The arithmetic is kept because a reader may still meet those pages; it was, however, repeatedly quoted
   about the wrong files. **It is not true of the `e_z` / `e_y` pair the chapter includes.** Measured from the
   committed PDFs: the first generation of that pair was `430.866 × 432` pt MediaBox, included at
   `0.95\textwidth` = `432.48` pt, i.e. at scale `1.003744`, and its smallest type printed at `8.29` pt
   (median `9.03`) — wrong, but not `3.5` pt wrong. The current generation is `430.866 × 547.2` pt, prints at
   `432.480 × 549.250` pt, and its smallest type is `11.04` pt. Any assertion that these figures print at `3.5` pt
   was mis-scoped to the superseded pages.

   Searching for this claim: it is written here with backticks around the number, so `grep '3\.5 *pt'` misses it.
   Search for `3\.5` alone.

The "honest options" that caveat 2 used to list — a rotated full-page float, a split into two half-figures, or a
redraw with fewer panels and larger type — were resolved the third way: the pair was redrawn at the printed width
(`make_before_after_figs.py`, see Provenance), so no placeholder, no rotation and no split is needed. Whether to
split each three-row composite further is still open and is not decided here.
