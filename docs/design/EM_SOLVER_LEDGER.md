# EM solver ledger

A persistent list of the open work on this solver, written so that it survives a
handoff. Every item here was carried across at least one session boundary, and
each one names the artefact that decides it. Nothing in this file is a plan for
new physics: it is a list of things that are *known to be unfinished*, with the
evidence that says so. When an item closes, its row changes status; it is not
deleted. New work gets a new ID at the end of the table.

## Status vocabulary

Four labels, used here and in the other design documents. Nothing else is a
status word.

| label | means |
|---|---|
| **VERIFIED** | Re-observed in this container, from a named command or a named file, and the observation is recorded next to the claim. |
| **OPERATOR-REPORTED** | Done on the operator's host and reported back. Not reproduced here. Quoted as the operator's report, never as a local observation. |
| **UNVERIFIED** | Believably true, believed by someone, but no artefact in this repository settles it. Do not build on it without producing that artefact. |
| **RETRACTED** | Was claimed, is now known to be wrong. Kept in place, with the correction, so the wrong number cannot come back as a fresh discovery. |

## How to use this file

- **New items get new IDs.** `E10` next; IDs are never reused and never renumbered, so a reference to `E2` in a commit message keeps meaning the same thing after the table grows.
- **Flip a status only on an artefact.** Moving something to VERIFIED means a named command or a named file now settles it; moving it to RETRACTED means something in the tree contradicts it. "I now believe it" is not an artefact.
- **Never delete a RETRACTED row.** The whole point of keeping it is that the wrong number stays visibly wrong; deleting it lets it return as a discovery in a later session.
- **Nothing here is a claim of correctness.** A closed row means the question is settled, not that the solver is right.
- **A row is a claim to be checked, not a settled fact.** E4's original premise was itself wrong, and was corrected on 2026-11-09 by re-reading the artefact rather than by reasoning about it.
