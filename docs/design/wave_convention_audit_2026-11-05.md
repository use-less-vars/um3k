# Wave-convention audit — 2026-11-05

Read-only (tree reading + one arithmetic pass). Question: can the pipeline's wave convention produce the common ~1.05–1.06 factor that |S11| and |S21| both show against the TE anchor (`complex_load_analysis_2026-11-04.md`:144-145)? Answer: **no**; Q3 and Q5 carry it.

## Q1 — where a_port, b_port, a_cut are defined

One algebra for all four: `emfit/studies.py:1294` `0.5*(v + sign*zc*i)*exp(sign*gamma*x)`, forward sign +1 (`:1351`), backward −1 (`:1375`); docstring `:1305-1316` states the model (`v = A e^-gx + B e^+gx`, `i = (A e^-gx − B e^+gx)/zc`, `A e^-gx = (v + zc i)/2`). These are **voltage travelling waves** referred to the run's own *complex* zc — not Kurokawa power waves (no `sqrt(Re Z)`), not Marks–Williams pseudo-waves (no `sqrt(Z)`), not raw V/I. Call sites `:3643-3650`: `a_port = forward(v_port, −i_trunc, x_port)`, `a_cut = forward(v_cut, i_cut, x_cut)`, `b_cut`/`b_port` the backward counterparts — four calls, one `zc_split`, one `gamma_split`. `run.loaded_without_reference` is true on this run, so `:3641` gives `gamma_split = 0j` and `zc_split = complex(station_fit.z0) = 47.364066848187235 + 1.6449807931078728j`.

## Q2 — where s11 and s21 are formed, and which Z0

s11: `emfit/ports.py:1513-1517` fits v and i separately at fixed beta — `z0 = A_v/A_i`, `gamma_v = B_v/A_v`, `gamma_i = B_i/A_i`; `emfit/studies.py:3563` takes `gamma_v`, `:3565` de-embeds it. The gated magnitudes are other estimates: `s11.magnitude` = |B/A| of `fit_beta(n_wave=2)` (writer `run_build_A.py:1724`), `magnitude_one_wave_station_fit` = one-wave `gamma_port` (`:1725`). s21: `emfit/studies.py:3651-3659` — `gamma_plane = b_cut/a_cut`, then `s21 = a_cut/a_port` de-embedded, via `line_s21` (`:1272-1279`: `raw = a2/a1`, then `deembed_transmission(raw, beta, d)`) or, with a twin, `reference.forward_ratio(x_port, x_cut)` — not this run. **Z0 in the s21 path: none** — no 50, no 47.54, no per-frequency array; the only impedance is `zc_split`, the complex fitted `station_fit.z0`, one scalar at one frequency. `line.z0 = res.z0 = 42.4379 − j15.7280` (port V/I) is a different quantity, unused here (the writer says so: `run_build_A.py:1627-1629`).

## Q3 — same wave definition on both paths? **YES**

`s11 = B_v/A_v` is the B/A of a wave pair whose forward V/I *is* `z0 = A_v/A_i`, the same zc the split uses; `s21 = a_cut/a_port` is evaluated with one `zc_split` and one `gamma_split` for both operands (`:3642`, `:3643-3650`). No sqrt, no 1/2, nothing differing between the two ports. What differs between the paths is the **estimator** (9-station two-wave fit vs two-plane ratio) and the extraction plane — not the wave definition. The four `z0`s in the artefacts are four different quantities, not four conventions.

## Q4 — de-embedding and reference planes for s21 as well as s11

Both, same beta, same distance: s11 `:3565` `deembed_reflection(gamma_measured, beta, d)` with `d = station_x[0] − x_port` (`:3562`); s21 `line_s21` → `deembed_transmission(raw, beta, d)` with `d = x_cut − x_port`. Both `d = 0.0072` m, both on the single beta `231.55331672912826` (the `:3387` fix collapsed the two). Planes: `s21_planes = (x_port, x_cut)` (`:3636`) — the far plane is the load's cut plane, where `Z_plane` is measured (`z_eff` from `v_load/i_load`), the near plane the source 7.2 mm upstream. Only **one** port sits on the measurement plane and the line between them is divided out, so the anchor's assumption (both ports on the plane where Z is measured) holds in the de-embedding sense only.

## Q5 — conversion factor to the anchor, and whether it can be common

For a **series** impedance in voltage waves referred to zc, current continuity plus `V1 − V2 = ZI` with `b2 = 0` gives `S21 = 2 zc/(2 zc + Z)` and `S11 = (Z − zc)/(Z + zc)` (ABCD: `2/(2 + Z/zc)`). The anchor prints `S21 = 2*Z0/(Z + Z0)` beside `S11 = (Z − Z0)/(Z + Z0)`, i.e. `S21 = 1 − S11` — the identity that belongs to `S11 = Z/(2Z0 + Z)`, `S21 = 2Z0/(2Z0 + Z)`, not to the pair it prints.
At `Z0 = zc = 47.364066848187235 + 1.6449807931078728j`, `Z = 82.11518049761072 − 20.78227124428749j`: `F = S21_anchor/S21_pipeline = Z0(Z + 2zc)/(zc(Z + Z0)) = (Z + 2zc)/(Z + zc) = 1.356146 + 0.065344j`, `|F| = 1.357720`, `arg = +2.759°` — **1.36, not 1.05**; at `zc = line.z0`, `|F| = 1.399668`, `+12.071°`. At `Z0 = 47.54` real the standard series pair gives `|S21| = 0.532931` against the anchor's `0.724087` (ratio 1.358689).
**Can a convention mismatch give a common ×1.05 on both? No, on two grounds.** (a) Every candidate normalisation constant — 1/2, `sqrt(Re Z0)`, `sqrt(Z0)` — multiplies the wave pair identically and cancels in *both* `B_v/A_v` and `a_cut/a_port`; a cross-port factor would need different zc at the two ports, and the code has one scalar (`:3642`), so inside the pipeline the factor is exactly 1. (b) The anchor's two formulas do not share a convention, so its implied factors are Z-dependent, not constant: at `Z0 = 47.54` real the measured/anchor ratios are **1.059732** (s11), 1.060780 (s11 one-wave), **1.055700** (s21) — 0.381 % apart; at the complex station-fit Z0 they are 1.030275 / 1.031294 and 1.055561 — **2.424 %** apart. The agreement tracks the Z0 chosen in the anchor, not anything the pipeline does.

## Brackets

**B1 fires** for the pipeline: voltage travelling waves, one definition, identical at both ports — the wave convention is excluded as the common scale (null result). **B2 does not fire**: no per-port normalisation difference exists, and no power- or pseudo-wave quantity appears in either path.

**B3 does not fire as written - corrected after checking which model the data obey.** The pair printed at `complex_load_analysis_2026-11-04.md`:144-145, `S11 = (Z - Z0)/(Z + Z0)` and `S21 = 2*Z0/(Z + Z0)`, is a **one-port load description**: as complex amplitudes the two sum to exactly 1, so `S21 = 1 - S11`. A two-port series-element pair would instead be `S11 = Z/(2*Z0 + Z)`, `S21 = 2*Z0/(2*Z0 + Z)`, giving `|S21| = 0.532931`. The doc does not state which model it intends, and that ambiguity deserves one line in a future DR entry. The measurements do discriminate. Measured `|s11|^2 + |s21|^2 = 0.32556486641109117^2 + 0.7644184907560716^2 = 0.690325`. Load model at Z0 = 47.54: `0.307214^2 + 0.724087^2 = 0.618682`, implying a common factor `k = 1.05632`, against the directly measured `f_s11 = 1.059732` and `f_s21 = 1.055700` - agreement to 0.2 % on both ports. Series model: `0.094380 + 0.284015 = 0.378395`, implying `k = 1.35070`, which would require `f_s11 = 1.35070` where it is 1.059732. The load reading is therefore the one the data obey, and the 1.36 factor derived in Q5 is correct arithmetic about a model the data reject: it must not be reported as a 36 % anchor error.

**What would settle it:** not a re-grade. The common-scale hypothesis and the choice of `Z0` are one equation with two unknowns (Q5), so no recomputation confined to the S-parameters can separate them. Three things could. (a) The instrument's own reference impedance and wave convention as recorded in the run metadata - no file in the tree states them. (b) The fixed-`R` load model: holding the nominal 50 ohm load resistance fixed turns the residual into a conductance mismatch, and it is the only test in hand that imports information from outside the S-parameters. (c) The half-step staggering test (2c). Re-grading against the series pair would grade the anchor against a model the measurements reject (B3) and would say nothing about the anchor's `Z0`.
