# S3 (partial) — status-header truthfulness

Chunk 2 owns this phase. It is started here only because the Phase 1 greps already prove at least one
status header false, and leaving that unrecorded would make S2 read as if the 27 headers could be trusted.

## Proven case

`docs/design/E11_residual_preregistration.md:3` states:

    **Status:** PREREGISTERED (no results yet). Closes when exit criteria met.

The file is dated 2026-11-09 (Gen 10, mtime proxy). The same file, `:11`–`:15`, carries an amendment of
2026-11-10:

    the preregistered 4.90 % (coarse mesh, two-wave) is superseded by **6.52 % (fine mesh, two-wave)**,
    raw -6.517281 % against Gamma_anchor

`:45`–`:46` repeats "6.52 % (fine mesh, two-wave) and 6.42 % (fine mesh, one-wave), raw -6.517281 and
-6.415728 per cent"; `:686` records that the value "went -4.904143 -> -6.517281 per cent two-wave".
`docs/design/GEN12_HANDOFF.md:48` confirms the reading: "E11 is open. Target after the 2026-11-10 amendment:
6.52 % (fine mesh, two-wave) / 6.42 % (one-wave); the coarse 4.90 % is superseded." The corroborating dispatch
row is `docs/design/dispatch_log.md:68` = `residual-retarget-2026-11-10`.

**Verdict: the header is stale.** The file was amended to carry a measurement and the front matter was never
re-stated. The second half of the header — "closes when exit criteria met" — is still true: E11 is open. So the
defect is one of two clauses, which is the harder kind: a partially true header reads as fully true, and a
reader who trusts line 3 will believe there are no results while line 11 publishes them.

`grep -rn "no results yet" docs/` returns only that line (plus the `dispatch_log.md:68` context), so this is an
isolated lapse, not a template applied tree-wide.
