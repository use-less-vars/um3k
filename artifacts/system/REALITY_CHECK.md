# REALITY_CHECK — what in `emfit` is real, what is a stub, and where the docs oversell

**Method.** Every row below is backed by something I executed or read in this tree *today*, not by a
handoff document. Commands that produced evidence (run from the repo root):

```
python3 server/poc_app.py --dump-state /tmp/def_state.json          # default boot page
python3 server/poc_app.py --input artifacts/reference_sim_volume.npz --dump-state /tmp/ref_state.json
python3 server/poc_app.py --list-keys                               # default structure
python3 server/poc_app.py --input artifacts/reference_sim_volume.npz --port 8098   # + curl → HTTP 200
python3 -m pytest tests/test_animation_volume.py -q                 # 21 passed
python3 -m pytest tests/test_energy.py tests/test_pml.py tests/test_abc.py -q   # 22 passed
python3 -m pytest --collect-only -q                                 # 94 files, 1,293 tests
python3 -c "np.load(...).files"  over every shipped *.npz           # key census, §"Data"
grep -rn "openems" / "characteristic mode" / "ModalPort"            # absence checks
```
(In this sandbox the repo `.venv` is a Python-3.12 tree while `python3` is 3.13, so these ran with
`PYTHONPATH=.venv/lib/python3.12/site-packages:.`; the code itself is unmodified.)

Verdict scale: **WORKING** = does what it says, and something checks it · **PARTIAL** = does it for
one case / one path, or works with a caveat that changes the answer · **SCAFFOLD** = code and
plumbing exist, nothing shipped exercises it end-to-end · **ABSENT** = not there.

## 1. Subsystem verdicts

| subsystem | verdict | evidence | what would make it real |
|---|---|---|---|
| **Solver — FDTD/FIT core** (`emfit/evolve.py`, `maxwell.py`, C++ kernel) | **WORKING, but gated only where it is easy** | Real operators and a real leapfrog march: `FITStepper:83`, `step:186`, `cfl_dt:74`, `RickerSource:272`, `Leapfrog:304`, `maxwell.FITSystem:30`; optional C++ kernel `src/emfit_core.cpp` + `src/bindings.cpp` parity-tested at **tolerance zero** against frozen Python goldens. Energy/conservation gates exist — `tests/test_energy.py:111 test_energy_exact_conservation`, `:128 test_pec_conservation`, `:160 test_cfl_bound_is_sharp`, `:209 test_wave_propagates_at_c` — and I ran `test_energy.py` + `test_pml.py` + `test_abc.py`: **22 passed**. **But**: those conservation gates live in a **closed PEC box**; there is **no gate with a PML attached**, and the shipped pipeline always runs *with* a PML (`pml.py:402`). | one energy/conservation test on a PML-terminated domain, with the absorbed work accounted (`pml.AbsorbedWork:211` is the hook) and a non-zero residue bound. |
| **Solver — absorbing *port* termination** | **ABSENT** | `emfit/ports.py:3-13` says it in the module docstring: `FITStepper` only pins PEC constraints, there is no resistive edge — *"So this module does not terminate anything. Instead it splits the standing [wave]"*. Reflections at the port are handled by **de-embedding two travelling waves**, not by absorbing them. `ModalPort.from_mode2d` (`modalport.py:194-296`) has **zero call sites**; `modal_harness.py` is only called from `tools/` and `tests/`; `grep 'import modal\|modalport\|ModalPort' emfit/studies.py` = 0. | either a real port boundary condition, or a document that states plainly "we do not absorb at ports; we decompose" — and removal of the two unwired modal-launch paths or a caller for them. |
| **Solver — S-parameter extraction** | **PARTIAL, and its own gate is RED** | The machinery is real (`ports.fit_beta:861`, `fit_line:1058`, `StationFit:1290`, `travelling_waves:681`, `modal.modal_sparams:685`) and writes real records (`evidence/termination/build_A_50ohm_p51_phasors.json`: `s11_two_wave=0.32556486641109117`, `s21_magnitude=0.7644184907560716`). But per `docs/design/pipeline_map.md`: gate **T4_amp** measures `R = 4.0489791163982565` against analytic `2.810102138752` = **44.09 % high** (Q = 1.4409), and five dense rungs + five fresh meshes hold it 15.7–44.1 % high, non-monotone; **T2_agree** is 4.52 % against a 0.5 % tolerance = 9.03×. The `validation_status` field in the record itself reads **`UNVALIDATED`**. The 0.5 % / ±10 % bands are themselves **uncited** (`F04` calls ±10 % "the standard engineering target" with no source). | an independent analytic anchor for *amplitude* (not just phase), agreement quoted against a citation, and a green T4/T2 on ≥3 resolutions. The openEMS referee (E12) is the declared route and **does not exist yet**. |
| **Data — the artefact contract** | **WORKING** (strict, and honest) | `load_vis:520` enforces 16 mandatory keys plus shape agreement (`ez_ycut == (nt,nx,nz)`, x-cuts equal and `(nt_x,ny,nz)`, `t_ns`/`frame_index`/axis lengths), refuses a foreign `schema` rather than falling back, treats a half-volume as no volume (`:630-644`, `:690-710`), refuses to truncate a load trace to the shorter array (`:470-527`), and computes one colour limit from all frames so the viewer *cannot* rescale per frame. Absent metadata reads as `None`/NaN and prints "not recorded". Richest shipped file: **`artifacts/reference_sim_volume.npz`, 46 keys, 40,407,762 B, `emfit.vis/2`, `ez_ycut (2400,62,22)` + `e_abs_volume (24,62,212,22)` at stride 100**, plus load trace + netlist JSON. | nothing structural — this is the soundest part of the repo. |
| **Data — coverage / provenance** | **PARTIAL — one usable case, and it is two runs glued** | `structures.json` has 3 entries; **2 are `"record only"`** (no dump on disk) and are refused on selection (`poc_app.py:1422`, `:1452`). The one openable entry points at `evidence/termination/build_A_50ohm_p51_ghostwave_fields.npz` — **11 keys, no `schema`**, i.e. dialect 2 (legacy), not the animated format. Its paired S-parameters are a **different solve**: the viewer's own state says `mismatch.flag=true`, *"Field dump is 62x212x22 but the S-parameter record is 72x212x22 … not the same solve."* Only **one** shipped file carries a volume, and **it is not reachable from the registry** — you need `--input artifacts/reference_sim_volume.npz` (`scripts/run_reference_sim.py:84`). | a registry entry (or auto-discovery) for `reference_sim_volume.npz`; one arm whose field dump and S-parameter record come from the **same** mesh; publish dumps for the "record only" arms or delete the entries. |
| **Charts** (S-params, port waves, load trace) | **WORKING as rendering, UNANCHORED as numbers** | Three matplotlib → base64 PNG data-URI sites: `poc_app.py:2063` (frequency chart), `:2317` (port-wave chart), `:2448` (load V(t)/I(t)). Each is fenced by `try/except` that prints `chart render skipped` and returns a reason instead of dying (server-safe). The frequency chart is `"mode": "markers-only", "interpolation": false` and marks ambiguous points — it does not draw a curve between sparse rows. **But** every chart is drawn from a JSON record, not from the fields on screen, and the record may be another run (previous row). | compute the plotted S-parameters from the loaded dump itself, or stamp every chart with the dump's `structure_id` + mesh and refuse when they disagree (the `mismatch` machinery already exists — use it to *block*, not just to annotate). |
| **3-D view** | **WORKING for planes + volume; ABSENT for far field** | Real PyVista geometry built from the dump's own node coordinates (`pv.ImageData` at `:8509`, `:8791`; `pv.Plotter(off_screen=True)` at `:4660`; overlays `pv.Box`/`pv.Plane`/`pv.Line` at `:7015-7139`), delivered to the browser through `trame_vtk` (`:5676`). Served headless: `curl` → **HTTP 200, 1,383-byte trame shell**, i.e. the HTML contains no content — every pixel is client-side WebGL, which is why a GL-less sandbox still "serves" but shows nothing in a screenshot. **Far Field tab is unreachable**: it needs `--surface-dump` with schema `emfit.surface-dump/1`; no shipped npz carries those keys, and the loader refuses one **by name** if given (`:790-807`). | ship (or generate on first run) one Huygens surface archive so the Far Field tab has a case; a browser-based smoke test that asserts a rendered pixel. |
| **Playback** (the two-clock player) | **WORKING — the best-tested subsystem in the repo** | `_volume_player_plan:9007` is a **pure function of `info`**, with asserted invariants (`steps == volume steps`, `frames == len(steps)`, `state.frame_max == len(steps)-1`, `plane[0]==0`, `axis[index]==steps[position]`, last frame lands on the last captured plane) and per-frame colour scale. `tests/test_animation_volume.py` → **21 passed** here, including `test_every_player_position_draws_one_time_step`, `test_the_plan_maps_the_boundaries_and_the_tail`, `test_a_dump_without_a_volume_keeps_the_plane_clock`, and the `desync_page` fixture ("3 captures, 12 planes"). It escapes the DR-47 class precisely because it is tested as a pure function, not through trame. | only: label the two clocks side by side in the readout (it currently prints the *plane* frame's time while the state is on the volume clock — correct, but easy to misread). |
| **Export** | **ABSENT** | `grep -n "Export\|export" server/um3k_panels.py` = **0 hits**. `grep -n "download\|to_csv\|savefig" server/poc_app.py` = only three `fig.savefig(buffer, format="png")` calls into memory (`:2063`, `:2317`, `:2448`). The only machine-readable output is the CLI diagnostic `--dump-state FILE` (`emfit.poc-state/3`) and `--list-keys`. A user can right-click a PNG; a user cannot get a CSV of |S11|, a PNG file, or a geometry dump. | one "save" per panel writing to `artifacts/` with provenance stamped (dump path + `structure_id` + mesh), and the `--dump-state` document promoted to the export path. |
| **Tests** | **WORKING in volume, blind at the UI seam** | **94 test files, 1,293 tests collected** (measured, this tree). Real gates on the physics and the data contract (energy/PML/ABC pass; the animation player passes 21/21). **But** the three UI claims that matter are protected only by comments: the tests that boot the app never let trame dispatch, so no `@state.change` listener runs — that is exactly the **DR-47** failure class, where an edit made `_start_watch → _watch_solve → _poll_solve → apply_page` unreachable with no exception, no failing test, and a page that never refreshed; it was caught only by a test asserting a string inside a closure. Panels also close over ~63 of their own closures and the page context does not reach them (`UM3K_UI_ARCHITECTURE.md` §3.6), which is the mechanical reason that class is possible. | drive the state machine in-process (call the listener bodies directly with a fake state) so `apply_page` is executed by a test; assert the *effect* (a rebuilt sheet), not a string in a closure. |

### One-line summary

The **physics core, the artefact contract and the playback player are real and checked**. The
**S-parameter numbers are unvalidated and 15–44 % off their own stated gate**, **absorbing port
termination does not exist**, **the GUI cannot export anything**, and **the app a newcomer boots is
not the app the design docs describe**.

## 2. Claims in the docs contradicted by the code

**Not contradicted — worth saying out loud**, because it is rare: the repo's own honesty conventions
are *kept* in the code. The registry decides "record only" by a filesystem check, never by a flag
(`:1422`); the readout reads `structure_id`/`load_ohm` from the **dump**, not from the registry, so a
copied dump cannot borrow another case's numbers (`:862`); a bare board page fills every unknown with
`NaN` rather than a plausible default (`:3691`, because draw sites test `isfinite()`); absent volume
keys read as `None`, never zeros. **The gap in this repository is not dishonesty, it is coverage.**
